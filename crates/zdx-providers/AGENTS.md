# zdx-providers

LLM provider implementations, used by `zdx-engine`.

## Layout

- `src/lib.rs` — crate root: module declarations, `ProviderKind`, `ProviderSelection`, `resolve_provider()`, `ProviderBuildContext`
- `src/shared.rs` — provider-agnostic helpers (`resolve_api_key`, `resolve_base_url`, `merge_system_prompt`, `USER_AGENT`, `streaming_http_client`); re-exports value types from `zdx-types`. Streaming model clients MUST build their HTTP client with `streaming_http_client()` (connect + per-read timeouts, no total timeout); a bare `reqwest::Client::new()` has no timeouts and let a silent socket hang a turn for hours (2026-10).
- `src/oauth.rs` — OAuth token storage/retrieval (Claude CLI, OpenAI Codex, Google Antigravity, Grok Build, Muse Code, GitHub Copilot). Claude CLI, Codex, Antigravity, and Grok Build use PKCE authorization-code with a localhost callback; `oauth::muse_code` and `oauth::github_copilot` use RFC 8628 device authorization. `oauth::github_copilot` follows Pi: VS Code Copilot Chat's client ID, `refresh` = GitHub `gho_` token (no expiry), `access` = Copilot token from `copilot_internal/v2/token` (expires within the hour, stored minus 5 min, re-exchanged via `refresh_locked`); the API host is read from the token's `proxy-ep`, so nothing else is stored. `oauth::muse_code` uses it because Meta exposes no redirect client, and it stores two credentials: `refresh` = Meta identity token, `access` = minted Model API key (`NO_EXPIRY`; replaced only via `remint_rejected_key`, a compare-and-swap under the cache lock so a concurrent process does not re-hit the rate-limited mint endpoint). Every call in this module uses a bounded HTTP client (connect + request ceilings) that **must** send a user agent and **must not** follow redirects: `auth.meta.com` answers a user-agent-less request with a 302 to `facebook.com/unsupportedbrowser`, and reqwest sends none by default, so following that redirect turns a rejected request into a confusing JSON parse failure on an HTML body (both device-code endpoints are affected; the `api.meta.ai` mint host currently is not). The device-code poll additionally bounds *both* its waits and each request/body-read by the grant's remaining lifetime, so it cannot outlive the advertised deadline nor accept a token that lands after the code expired — the client's fixed timeout is only a per-request upper bound.
- `src/anthropic/` — Anthropic Messages API + Claude CLI OAuth provider
- `src/openai/` — OpenAI Responses/Chat Completions API + Codex OAuth provider. Images: `images_api.rs` is the one Images API client (`/images/generations`, `/images/edits`) with two auth modes: API key (`api.openai.com/v1`, GPT Image 2.6 and its controls) and the Codex subscription (`chatgpt.com/backend-api/codex`, headers from `codex::build_json_headers`). Only the subscription baseline (`gpt-image-2` alias, `size`/`quality` `auto`, `background` `opaque`) was live-verified, for generation, 2026-11-05; edits there are untested
- `src/gemini/` — Google Gemini API + Antigravity OAuth providers
- `src/openrouter.rs`, `src/deepseek.rs`, `src/mistral.rs`, `src/moonshot.rs`, `src/stepfun.rs`, `src/minimax.rs`, `src/xai.rs`, `src/lmstudio.rs` (local server), `src/xiaomi_plan.rs` (MiMo Token Plan) — thin OpenAI-compatible providers; `src/xiaomi.rs` and `src/zai.rs` are too, with the quirks below
- `src/alibaba.rs` — Alibaba DashScope chat completions; `src/alibaba/image.rs` — Qwen-Image generation and editing
- `src/zai.rs` — Z.AI GLM. The GLM-5.3 family always reasons: it 400s on `thinking: {"type": "disabled"}` (code 1210) and accepts only `reasoning_effort` `low|high|max`, so that family gets no thinking toggle and carries the level as a top-level effort instead; other GLM models keep the documented enabled/disabled toggle (verified against `api.z.ai` 2026-09-15).
- `src/meta.rs` — Meta Muse Wonder and Muse Spark over the Responses API. Reasoning cannot be disabled: `effort: "none"` is HTTP 400 and omitting `reasoning` hands depth to the model (~118 reasoning tokens for a one-line answer vs 5 at `minimal`), so `off` sends `minimal` with no summary. `max` is accepted by `muse-wonder-full-1.0`, `muse-wonder-1.0`, `muse-wonder-1.0-contributor` (Muse Code only), and Standard-tier `muse-spark-1.3`; `muse-spark-1.3-contributor` 400s, so other ids clamp to `xhigh` (verified live 2026-09-16 and 2026-10-12; docs: dev.meta.ai/docs/reasoning). `muse-wonder-1.0-contributor` and `muse-wonder-full-1.0` exist only on Muse Code subscriptions; the Model API key returns 404 for both. Wonder Full also needs the Power Usage or Maximum Usage plan (404 on High Usage).
- `src/grok_build.rs` — Grok Build provider: xAI Grok subscription OAuth over the Responses API at `cli-chat-proxy.grok.com` (bearer from `oauth::grok_build`, refreshed on demand). Subscription tokens must go to the proxy with Grok CLI client headers: `api.x.ai` answers 402 `personal-team-blocked:spending-limit`, and the proxy answers 426 when the headers are missing or `GROK_CLI_VERSION` is below its minimum (bump it to the current stable from `https://x.ai/cli/stable`)
- `src/github_copilot.rs` — GitHub Copilot provider: one subscription, three wire APIs. Routes by the registry `api` hint, else `api_for_model` (Claude → Anthropic Messages with bearer auth via `AnthropicClient::send_messages_stream_bearer`; GPT-5+ except `gpt-5-mini`, Grok, MAI, OSWE → Responses; the rest → Chat Completions via `send_messages_stream_with`). `zdx models update` stores the same `api_for_model` result, because models.dev tags every Copilot model `@ai-sdk/openai-compatible`. Every request carries VS Code identity headers plus per-request `X-Initiator`, `Openai-Intent`, and `Copilot-Vision-Request` (see SPEC §GitHub Copilot). `GITHUB_COPILOT_BASE_URL` overrides the token-derived base URL (tests use it). Copilot names Claude models with dots (`claude-sonnet-4.6`); `anthropic::shared::normalize_model_id` maps dots to dashes for capability checks. ⚠️ Presents VS Code's identity, which GitHub does not authorize for third-party clients. Unverified against a live account: model policy enabling, Gemini/Kimi on Chat Completions, and Claude thinking on Copilot's Messages endpoint.
- `src/muse_code.rs` — Muse Code provider: Meta subscription over the same Responses shape as `meta.rs` (shares `meta::responses_config`), authenticated with a Model API key minted by `oauth::muse_code`. The key has no published lifetime, so it is stored with `NO_EXPIRY` and never proactively re-minted; a 401/403 from the Responses call triggers exactly one `remint_rejected_key` + retry. Every tool goes on the wire as `_<name>` (`TOOL_NAMES`, via `tool_names` and `send_responses_stream_named`): Meta answers a declared client-tool name such as `bash` with 403 `client_attestation_denied`, which is never re-minted. ⚠️ Meta documents the subscription as CLI-only; whether a key minted here bills to the subscription or pay-as-you-go is **unverified** (no billed request was made). Because zdx zeroes pricing for every subscription provider (`models.rs` `push_candidate`), muse-code reports $0 cost — if billing is actually pay-as-you-go, that under-reports. Protocol follows the MIT-licensed `oh-my-pi`; that license covers code reuse only, not Meta service authorization.
- `src/openai_compatible.rs` — generic OpenAI-compatible chat-completions client for user-defined "custom" providers (`[providers.custom.<name>]`, the default `api = "chat-completions"`); carries no `ProviderKind`, built directly by the engine from a resolved base URL + API key. Forwards the model spec's thinking level as a top-level `reasoning_effort` string; `off` sends `"none"` because proxied reasoning backends (DeepSeek) think by default, and a LiteLLM-style proxy honors `none` while dropping DeepSeek's `thinking.type = "disabled"` (verified live 2026-09-17). Custom providers with `api = "anthropic"` reuse `AnthropicClient` via `anthropic::api::build_custom` (same budget/effort mapping as the first-party provider, `x-api-key` auth, and `explicit_thinking_off` so `off` sends `thinking: {"type": "disabled"}` instead of omitting it); the engine strips one trailing `/v1` from `base_url` first because the client appends `/v1/messages`. The engine picks the protocol from an explicit per-model `api` override before the provider `api`; keep `explicit_thinking_off` false on every other `AnthropicConfig` site until a backend is verified to accept the value.
- `src/xiaomi.rs` — Xiaomi MiMo uses a binary `thinking.type = enabled|disabled` toggle; all non-off ZDX levels map to `enabled`. MiMo defaults to thinking on, so proxy routes must send `disabled` explicitly for `@off`. In thinking mode, every `reasoning_content` value from a historical turn that used tools must be replayed in full or a later request can fail with HTTP 400 (verified against Xiaomi's V2.6 API docs 2026-09-22). Historical replay is an explicit chat-completions config opt-in enabled only by Xiaomi, Xiaomi Plan, and MiMo through OpenCode Go; never infer it from a model name in the shared serializer because custom/local providers may reuse that name without sharing Xiaomi's wire contract.
- `src/audio_chat.rs` — one-shot audio understanding for `ask_media` over non-streaming Chat Completions with an `input_audio` part. Builds, sends, and parses the request from validated `AudioSettings` (payload shape, formats, base64 limit, `max_tokens`, `modalities`); it holds no per-provider values. Those come from config (shipped defaults in `zdx-assets/audio_providers.toml`, `[providers.<name>.audio]`, or `[providers.custom.<name>.audio]`), and which models take audio is the `input_audio` override field (`models::model_audio_input`). Declare a model only after its provider documents audio input for it and a synthetic clip works; a model in a text registry is not proof (`voxtral-mini-latest` answers 400 `Invalid model` on chat, verified 2026-10-28). The caller resolves the endpoint and auth (`AudioAuth::Bearer` with a resolved key, or `AudioAuth::MuseCode`, which re-mints once on 401/403 like `muse_code.rs`).
- `src/embeddings.rs` — hosted text-embeddings client (OpenAI-compatible `/embeddings`); explicit opt-in corpus/query embedding for native memory — batching, budgets, and persistence live in `zdx-engine`
- `src/opencode_go.rs` — meta-provider that routes to inner clients based on model registry hints; every route sends `x-opencode-session` using collision-safe encoding of the thread/conversation id, or a client-scoped UUID for one-shot threadless runs. Threadless TUI chats supply a stable conversation id across turns.
- `src/debug_metrics.rs`, `src/debug_trace.rs` — debug/tracing wrappers for provider streams
- `src/thinking_parser.rs` — SSE stream content parser
- `src/tool_names.rs` — per-provider tool names on the wire (`ToolNamePolicy`, `ToolNames`): maps declared tools and replayed tool calls to wire names, and streamed tool calls back; unknown wire names pass through

## Conventions

- Pure value types (DTOs, enums) belong in `zdx-types`, not here.
- This crate must NOT depend on `zdx-engine` (no circular deps).
- `zdx-engine` re-exports everything via a thin `providers.rs` facade.
- Provider routing hints (e.g. for the opencode-go meta-provider) are passed as `api_hint: Option<String>` parameters — model registry lookups happen in the caller (`zdx-engine`).

### OAuth credentials

- `oauth.json` is rewritten whole on every change, and providers rotate the refresh token on each refresh. Any read-modify-write MUST hold the cross-process lock (`<zdx home>/oauth.lock`): use `OAuthCache::update` for writes and `oauth::refresh_locked` for refreshes. `OAuthCache::save` is atomic (temp file + rename, 0600) but does not lock on its own.
- `refresh_locked` re-reads the cache after taking the lock and returns the stored credentials when another process already refreshed, so a rotated refresh token is never replayed. Provider `resolve_credentials` must not refresh or persist tokens itself.

### Request logging

- Every streaming request site MUST go through `shared::log_request(client, url)` before sending and `shared::check_response_status(client, response)` for the status check. `check_response_status` owns the non-success path (log + `ProviderError::http_status`); do not hand-roll it.
- `client` is the request implementation label so callers sharing a helper stay distinguishable. Streaming: `anthropic`, `claude-cli`, `openai`, `codex`, `xai`, `grok-build`, `github-copilot` (all three Copilot routes), `chat-completions`, `gemini`, `google-antigravity`. Non-streaming: `gemini-image`, `gemini-media`, `audio-chat`, `openai-image`, `codex-image`, `alibaba-image`.
- MUST NOT log headers, request bodies, or full URLs. `endpoint_label` intentionally keeps only host + path: a configured base URL may embed `user:pass@` and some APIs accept `?key=`.
- Error bodies are truncated **and** whitespace-collapsed (`truncate_body`) so one event is always one log line — pretty-printed JSON would otherwise break line-oriented log viewers such as the monitor's Logs tab.
- Do not log the model here; the engine's `turn` span already carries it. Providers must not reach for engine state — rely on parent-span context.
