# zdx-monitor

Compact TUI dashboard for inspecting ZDX services, threads, jobs, and config.

## Files

Layout rule: `src/tabs/` holds one module per tab, co-locating that tab's state types, key handlers, data loading, and `render_*` functions (monitor is a tick-loop app, not MVU — a change to one tab should touch one file). `app.rs` keeps the flat `MonitorApp` struct, the loop, and top-level routing; `ui.rs` keeps only the `render()` dispatch and cross-tab widgets. Keep new tab work inside its `tabs/` module and put helpers in `app.rs`/`ui.rs` only when genuinely shared by 2+ tabs.

- `src/lib.rs`: crate entry, re-exports `run()`, declares `app`/`log_line`/`tabs`/`ui`
- `src/app.rs`: `MonitorApp` (one flat struct holding every tab's fields), tick/event loop (`run`, `refresh_app`, `build_app`), terminal setup, and top-level input routing. Tabs are the `Section` enum (exhaustive `ALL`/`next`/`label`/`item_count`). Keyboard entry goes through `handle_key_event`, which applies the vim `g` prefix before `dispatch_key_event`: **`gg` is translated to `Home`** (unknown `g` sequences are swallowed like vim), so every scroll surface binds `Home`/`End` (+ `G`) for top/bottom instead of a single `g` — keep that convention (and `text_input_active`) in mind when adding keys or new text-entry modes. `handle_mouse_event` takes the whole `MouseEvent` because clicks need the row; `handle_overlay_mouse` routes it while any overlay is open so wheel scrolling never leaks to the list underneath, and after an overlay closes a self-extending `scroll_guard_until` swallows the trackpad's inertia tail. Cross-tab shared items live here: `TargetPickerState` (fuzzy picker state behind both the Logs target filter and the Threads project picker), the `copy_text`/`lines_text` copy helpers, and `open_path_in_editor`.
- `src/log_line.rs`: `tracing` compact log-line parsing (`LogParts`: timestamp/level/span-scope/target/message) plus the Logs-tab filter primitives (`LevelFilter`, `line_matches`). Shared by `tabs/logs.rs` (filtering + coloring).
- `src/ui.rs`: top-level `render()` dispatch plus cross-tab widgets only: tab bar, footer hints, `render_picker` (Logs target filter + Threads project filter), `centered_rect`, `truncate_chars`, `spinner_frame_now`, `SELECTED_BG`.
- `src/tabs/mod.rs`: tab module exports
- `src/tabs/agents.rs`: Active Agents tab + transcript overlay. The overlay (`AgentOverlayState`) keeps the `HistoryCell`s plus a `ToolRef` per tool call and a `ThinkingRef` per thinking block (each with its `line..end` row span), so `Tab`/`n`/`p` highlight a tool, `Enter` opens it, and a left click anywhere in a tool's rows opens it directly (`handle_overlay_click` → `open_tool_pane_at_row`; the overlay is full-frame, so screen row = content row + 1). Row spans come from `cell_end_row`, which subtracts `zdx_transcript::gap_after` rather than assuming one trailing blank — consecutive tool/thinking cells render with no separator. Thinking blocks render collapsed; a click toggles one (`toggle_thinking_at_row`, which anchors the clicked row so the view does not jump) and `t` toggles all (`toggle_all_thinking`). Expansion lives in `expanded_thinking` as ordinals rather than on the cell, because cells are rebuilt from disk on refresh; `rerender_transcript` re-renders from the cells already in memory so a toggle never re-reads the JSONL. The pane itself is `ToolPaneState`, keyed by `tool_use_id` so running tools keep updating; `render_tool_pane` renders `zdx_transcript::tool_detail_body`, the same body the chat TUI's tool popup shows. The Threads tab reuses `AgentOverlayState` via `load_transcript_into` (a saved thread is an ended run).
- `src/tabs/logs.rs`: Logs tab. Raw tailed lines live in `MonitorApp::log_lines` plus a derived `log_visible: Vec<usize>` of indices passing `log_level_filter` (`l`) and `log_query` (`/`); `log_selected`/`log_offset` are positions in `log_visible`, and `MonitorApp::selected_log_line()` is the only raw-line accessor (overlay + `y` copy). `recompute_log_visible` wraps the pure `visible_log_indices` + `clamp_log_view`. Filters are level (`l`), target prefix (`f`, via `TargetPickerState`), and substring query (`/`); `Esc` clears all. `log_files`/`log_file_index` list `zdx.log*` newest-first for `[`/`]` day switching, `log_tail_lines` is cycled by `L`, and `LoadedLogFile` stamps (path+len+mtime+tail) keep `load_active_log` from re-reading an unchanged file each tick.
- `src/tabs/threads.rs`: Threads tab handlers, browse query + project picker, transcript preview, and the `i` trajectory overlay, which renders the shared `zdx_engine::core::thread_trajectory` projection/formatter and keeps selection/filter state untouched (see "Threads tab" below).
- `src/tabs/config.rs`: Config tab — views one `zdx_engine::workspace_config::Scope` at a time: the workspace at `config_workspace_index` (default the monitor root) or, with `config_global_view`, the global config alone. `p` opens the picker (global first, then workspaces, re-discovered on open; each row shows `workspace_config::own_override_count`, `(?)` when the layers fail to load, and `render_picker` trims the label end so the count always fits, which is why the path goes last); `a` toggles workspace ↔ global on the same row. `MonitorApp::root` stays the monitor root for the other tabs. `load_config_view(scope)` loads only that scope's layers: effective values, field origins, and the shared `Setting`s (inherited value/source per key); `config_reach` holds `workspace_config::reach` for the viewed file. `config_sources` holds `RowSource` tags (own-overlay tags highlighted, ancestor tags dim) separately from raw `ConfigLine` values so provenance never enters the picker path. Rows map to shared setting keys through `setting_key`. Every write and reset goes through `request_change`, which targets `scope.file()`; it builds a `PendingWrite` that captures the destination file, and when `scope.writes_global_file()` (global view, or a workspace with `overlay_is_global`) or the write carries a `note` (deleting an inherited mode copies the rest of the list) it parks it in `config_confirm` until `y` (`render_pending_write`; `y` writes the captured file). While it is pending, `handle_config_key` and `handle_overlay_mouse` swallow every other key and mouse event. Mode edits/deletes and the subagents toggle start from `effective_config`, the viewed chain, which is the destination's chain. The header strip (`header_lines`, wrapped by `wrap_words` to the panel width, at most `MAX_HEADER_ROWS`; `config_page_size` uses the same height) names the destination and shows the selected row's origin, reset fallback, and reach. `config_footer_hint` is the Config footer (it names `a`'s target and the confirm keys). `open_workspace_picker` reloads the view when the viewed workspace disappeared, so rows and destination never diverge. Also owns the model picker (`ModelPickerState`, model → thinking-level phases; `PickerTarget::Config(ConfigDestination)` names and colors the destination), model-mode editing (primary only; `mode:<name>` refs offered for subagent rows), and subagent toggling. Config keys route through `handle_config_key`, which also owns the open workspace picker and the pending confirmation. `g` is not usable as a key here: the vim `gg` prefix swallows it.
- `src/tabs/usage.rs`: Usage tab — cached usage scan + subscription quota fetch (both polled async via channels on the refresh tick) and the charts/tables rendering stack.
- `src/tabs/background.rs`: Background tab — lists running background processes from `zdx_engine::background_activity` (`load_background()` → `BackgroundInfo`, sorted by thread); `x` kills the selected one (`kill_selected_background`, async on a scratch Tokio runtime) and `Enter` opens a full-frame detail overlay (`BackgroundDetailState`, keyed by `bg_id`): marker metadata, the full command, and the stdout/stderr log tails (`background_activity::read_log_tail`, 64 KiB per stream), rebuilt pre-wrapped on the refresh tick (`refresh_background_detail`) so a running process keeps streaming; it opens in follow mode (pinned to newest output, `G` re-follows, scrolling up detaches). `render_background` groups rows under per-thread headers.
- `src/tabs/services.rs`: Services tab actions + rendering (see "Services tab" below).
- `src/tabs/jobs.rs`: Jobs tab. `load_jobs` is a thin call to the shared `zdx_engine::job_daemon::jobs()`, so settings are resolved the way the scheduled daemon resolves them (its running record, else its installed service), never for `MonitorApp::root`, and status, next run, last outcome, and model/root provenance are never re-derived here. It reads the daemon record, plist, config, claim, and subagent files, so it runs on entry to the tab (`switch_section`), not on the tick. The title names the daemon source and root; the list is width-aware (name → status → schedule → model spec → root; inherited values end in `*`; red status when a job is invalid, expired, interrupted, or its last run did not succeed); the lower pane shows schedule, status with next/last run, the last error, and declared vs resolved settings with origins, or the resolution error (including "daemon settings unavailable" and invalid files). Values are resolved now, not a past run's settings. `Enter` reuses the Config tab's `ModelPickerState` (with `PickerTarget::Job`) to set the job's `model:` through `jobs::set_model`, guarded by the declared model seen at open; `d`/`Delete` clears it. Each save reloads the daemon view and keeps the selection on the same job. `a` switches to a read-only list of archived once jobs (`JobsHome::archived`, loaded on the key press; `MonitorApp::jobs_archived`) and back; re-entering the tab returns to the jobs list.

## Threads tab

Rows come from `zdx_engine::core::thread_index::browse_threads()` (`threads.sqlite`), never a directory scan: kind, project, text filter, ordering, and the 500-row cap are all applied in SQL. Child runs are included and labelled with a badge (`subagent_name` for `subagent`, the suffix for `helper:*`); orchestrator workers get a `worker` badge from the engine's `is_worker_lineage`. `t` cycles `ThreadKindFilter`, `p` opens the project picker fed by `browse_projects()`, `/` edits the query, `Esc` clears all, `Enter` opens the transcript overlay, and `o` temporarily restores the terminal to open the raw JSONL in `$VISUAL`/`$EDITOR` (or the system default) before resuming Monitor. The query runs on `Enter` rather than per keystroke — a one-letter FTS prefix matches most of the corpus and would stall the UI. The preview reuses `AgentOverlayState` (a saved thread is an ended run), so tool navigation and the tool pane come for free.

## Services tab

The **Services** tab is a control panel over launchd, not a supervisor. `load_services()` maps `zdx_engine::service::Service::ALL` through `service::state()`. `Enter` delegates to `start`/`stop`, `r` requests a guarded restart, and `R` explicitly forces restart through active agent work. Restart runs on a background thread (`RestartJob` in `MonitorApp::restart_job`, collected by `poll_restart_result` in `refresh_app`) because `service::restart` waits for the replacement PID and launchd's `ThrottleInterval` can defer that spawn by up to ~10s; running it inline froze the UI. While a job is in flight the row shows `restarting`, the status stays pinned, and further `r`/`R`/`Enter` are refused. Monitor never spawns service processes itself, so restart always picks up `~/.local/bin/zdx` rather than the binary the monitor was launched from. Lifetime (login start, crash restart, `/restart` exit) belongs to launchd; install the agents with `zdx service install`.
