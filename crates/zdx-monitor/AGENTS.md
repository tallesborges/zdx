# zdx-monitor

Compact TUI dashboard for inspecting ZDX services, threads, automations, and config.

## Files

Layout rule: `src/tabs/` holds one module per tab, co-locating that tab's state types, key handlers, data loading, and `render_*` functions (monitor is a tick-loop app, not MVU — a change to one tab should touch one file). `app.rs` keeps the flat `MonitorApp` struct, the loop, and top-level routing; `ui.rs` keeps only the `render()` dispatch and cross-tab widgets. Keep new tab work inside its `tabs/` module and put helpers in `app.rs`/`ui.rs` only when genuinely shared by 2+ tabs.

- `src/lib.rs`: crate entry, re-exports `run()`, declares `app`/`log_line`/`tabs`/`ui`
- `src/app.rs`: `MonitorApp` (one flat struct holding every tab's fields), tick/event loop (`run`, `refresh_app`, `build_app`), terminal setup, and top-level input routing. Tabs are the `Section` enum (exhaustive `ALL`/`next`/`label`/`item_count`). Keyboard entry goes through `handle_key_event`, which applies the vim `g` prefix before `dispatch_key_event`: **`gg` is translated to `Home`** (unknown `g` sequences are swallowed like vim), so every scroll surface binds `Home`/`End` (+ `G`) for top/bottom instead of a single `g` — keep that convention (and `text_input_active`) in mind when adding keys or new text-entry modes. `handle_mouse_event` takes the whole `MouseEvent` because clicks need the row; `handle_overlay_mouse` routes it while any overlay is open so wheel scrolling never leaks to the list underneath, and after an overlay closes a self-extending `scroll_guard_until` swallows the trackpad's inertia tail. Cross-tab shared items live here: `TargetPickerState` (fuzzy picker state behind both the Logs target filter and the Threads project picker), the `copy_text`/`lines_text` copy helpers, and `open_path_in_editor`.
- `src/log_line.rs`: `tracing` compact log-line parsing (`LogParts`: timestamp/level/span-scope/target/message) plus the Logs-tab filter primitives (`LevelFilter`, `line_matches`). Shared by `tabs/logs.rs` (filtering + coloring).
- `src/ui.rs`: top-level `render()` dispatch plus cross-tab widgets only: tab bar, footer hints, `render_picker` (Logs target filter + Threads project filter), `centered_rect`, `truncate_chars`, `spinner_frame_now`, `SELECTED_BG`.
- `src/tabs/agents.rs`: Active Agents tab + transcript overlay. The overlay (`AgentOverlayState`) keeps the `HistoryCell`s plus a `ToolRef` per tool call and a `ThinkingRef` per thinking block (each with its `line..end` row span), so `Tab`/`n`/`p` highlight a tool, `Enter` opens it, and a left click anywhere in a tool's rows opens it directly (`handle_overlay_click` → `open_tool_pane_at_row`; the overlay is full-frame, so screen row = content row + 1). Row spans come from `cell_end_row`, which subtracts `zdx_transcript::gap_after` rather than assuming one trailing blank — consecutive tool/thinking cells render with no separator. Thinking blocks render collapsed; a click toggles one (`toggle_thinking_at_row`, which anchors the clicked row so the view does not jump) and `t` toggles all (`toggle_all_thinking`). Expansion lives in `expanded_thinking` as ordinals rather than on the cell, because cells are rebuilt from disk on refresh; `rerender_transcript` re-renders from the cells already in memory so a toggle never re-reads the JSONL. The pane itself is `ToolPaneState`, keyed by `tool_use_id` so running tools keep updating; `render_tool_pane` renders `zdx_transcript::tool_detail_body`, the same body the chat TUI's tool popup shows. The Threads tab reuses `AgentOverlayState` via `load_transcript_into` (a saved thread is an ended run).
- `src/tabs/logs.rs`: Logs tab. Raw tailed lines live in `MonitorApp::log_lines` plus a derived `log_visible: Vec<usize>` of indices passing `log_level_filter` (`l`) and `log_query` (`/`); `log_selected`/`log_offset` are positions in `log_visible`, and `MonitorApp::selected_log_line()` is the only raw-line accessor (overlay + `y` copy). `recompute_log_visible` wraps the pure `visible_log_indices` + `clamp_log_view`. Filters are level (`l`), target prefix (`f`, via `TargetPickerState`), and substring query (`/`); `Esc` clears all. `log_files`/`log_file_index` list `zdx.log*` newest-first for `[`/`]` day switching, `log_tail_lines` is cycled by `L`, and `LoadedLogFile` stamps (path+len+mtime+tail) keep `load_active_log` from re-reading an unchanged file each tick.
- `src/tabs/threads.rs`: Threads tab handlers, browse query + project picker, transcript preview, and the `i` timing overlay, which uses the shared `zdx_engine::core::thread_timing` reducer/formatter and keeps selection/filter state untouched (see "Threads tab" below).
- `src/tabs/config.rs`: Config tab — `ConfigLine` flattening of the effective config, the model picker (`ModelPickerState`, model → thinking-level phases), favorites editing, and subagent toggling.
- `src/tabs/usage.rs`: Usage tab — cached usage scan + subscription quota fetch (both polled async via channels on the refresh tick) and the charts/tables rendering stack.
- `src/tabs/background.rs`: Background tab — lists running background processes from `zdx_engine::background_activity` (`load_background()` → `BackgroundInfo`, sorted by thread); `x` kills the selected one (`kill_selected_background`, async on a scratch Tokio runtime) and `Enter` opens a full-frame detail overlay (`BackgroundDetailState`, keyed by `bg_id`): marker metadata, the full command, and the stdout/stderr log tails (`background_activity::read_log_tail`, 64 KiB per stream), rebuilt pre-wrapped on the refresh tick (`refresh_background_detail`) so a running process keeps streaming; it opens in follow mode (pinned to newest output, `G` re-follows, scrolling up detaches). `render_background` groups rows under per-thread headers.
- `src/tabs/services.rs`: Services tab actions + rendering (see "Services tab" below).
- `src/tabs/automations.rs`: Automations tab list + rendering.

## Threads tab

Rows come from `zdx_engine::core::thread_index::browse_threads()` (`threads.sqlite`), never a directory scan: kind, project, text filter, ordering, and the 500-row cap are all applied in SQL. Child runs are included and labelled with a badge (`subagent_name` for `subagent`, the suffix for `helper:*`). `t` cycles `ThreadKindFilter`, `p` opens the project picker fed by `browse_projects()`, `/` edits the query, `Esc` clears all, `Enter` opens the transcript overlay, and `o` temporarily restores the terminal to open the raw JSONL in `$VISUAL`/`$EDITOR` (or the system default) before resuming Monitor. The query runs on `Enter` rather than per keystroke — a one-letter FTS prefix matches most of the corpus and would stall the UI. The preview reuses `AgentOverlayState` (a saved thread is an ended run), so tool navigation and the tool pane come for free.

## Services tab

The **Services** tab is a control panel over launchd, not a supervisor. `load_services()` maps `zdx_engine::service::Service::ALL` through `service::state()`. `Enter` delegates to `start`/`stop`, `r` requests a guarded restart, and `R` explicitly forces restart through active agent work. Monitor never spawns service processes itself, so restart always picks up `~/.local/bin/zdx` rather than the binary the monitor was launched from. Lifetime (login start, crash restart, `/restart` exit) belongs to launchd; install the agents with `zdx service install`.
